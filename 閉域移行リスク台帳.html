01

ライブ検索

✕落とす

閉域だから落とすのではなく、これだけデータの向きが逆だから落とします。他の機能は「外→内」なのでゾーンを分ければ解決しますが、ウェブ検索は「内→外」──ユーザーが打った質問文がそのまま DuckDuckGo へ飛びます。経営会議で未公表の数値や固有名詞を含む質問を打った瞬間に外部送信され、ネットワークをどう組んでも防げません。

幸い改修は数行です。web_search_toggle は既に value=False で既定 OFF、呼び出しも if use_web: で完全に囲われているため、切ってもアプリは壊れません。

失うのは「任意のクエリで今この瞬間を引く」機能だけ。ニュース見出しと本文抜粋は news_rss を日次収集しているので閉域でも残ります。

対処

  • 既定 OFF → 設定で強制 OFF・トグル非表示に変える
  • 代替は事前収集した公開情報の社内 RAG 検索（data_external/public_sources が既にある）

02

LLM 機能

○閉域のまま使える

Bedrock の Interface VPC エンドポイント（PrivateLink）を使えば、インターネットに一切出ずに AWS 網内で完結します。閉域環境での標準解です。

現在の接続先 bedrock-mantle.ap-northeast-1.api.aws/anthropic は確かに Bedrock です（ANTHROPIC_API_KEY は ABSK… で始まり、デコードすると BedrockAPIKey-…-at-<アカウントID>）。ただし標準の bedrock-runtime エンドポイントではなく Anthropic 互換ゲートウェイで、PrivateLink が提供されているのは標準ホスト名のほうです。

ここだけ先に確認が必要です。ai_client.py に「提供状況は契約で変わる」と明記されており、今のゲートウェイは特定契約に紐づいている可能性が高い。自社アカウントの標準 Bedrock（ap-northeast-1）に Opus 4.8 / 4.7 / Haiku 4.5 が無ければ、モデル選定からやり直しになります。

対処

  • 標準 bedrock-runtime ＋ IAM ロール（SigV4）へ寄せる。anthropic.Anthropic(api_key, base_url) を AnthropicBedrock() に差し替えるだけ。モデル ID は既に Bedrock 形式なので改修は小さい
  • 副次効果として 長期有効な API キーが不要になり、CloudTrail に呼び出し履歴が残る（監査要件を満たしやすい）
  • あわせて .env 平文のシークレット一式を Secrets Manager へ

03

外部データ API（統計・IR・ニュース・SNS）

○取得ゾーンを分ければ使える

アプリを閉域に置くことと、データ取得を閉域でやることは別の話です。取得だけを別ゾーンに追い出せば両立します。

そして現状のコードは既にその形に近い。news_feed.py の冒頭に「取得はパイプライン側で行い、ここは保存済み JSON を読むだけ。画面からは通信しない」と明記され、実際に collectors → runtime_data の JSON → UI が読むだけになっています。ENABLE_PIPELINE_REFRESH という取得の ON/OFF スイッチも既にある。これが移行コストを大きく下げます。

対処

  • 収集を EventBridge Scheduler ＋ ECS Fargate へ切り出す。周期は refresh_policy.py に既に定義済み（6時間／日次／週次／月次）なので、そのまま写せる
  • S3 を一方通行にする。バケットポリシーで収集側は PutObject のみ、閉域側は GetObject のみ。機密データが外へ出る経路が構造的に存在しないので、監査で説明しやすい
  • アプリ側は EFS ＋ 同期サイドカー。MONITORING_TARGET_DIR の向き先を変えるだけで、アプリ本体のコード変更はほぼゼロ
  • S3 の手前に検疫層（スキーマ検証・サニタイズ）を置く。外部 RSS 本文が LLM プロンプトに入るため、機密投入後はプロンプトインジェクション対策としても要る
