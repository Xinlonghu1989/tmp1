2センシング（センシングボード）

6事業の外部環境と内部KPIを一画面で見て、今どの事業を優先して確認すべきかを判断する画面です。

操作の手順

  1. 左メニューの センシング を開きます。
  2. 画面上部の帯で、公開データがいつ時点のものかを確認します。
  3. その下の一文で、閾値を超えている指標が何件あるかを確認します。
  4. 6事業のカードで信号色を見て、気になる事業のカードを押します。
  5. 右側の詳細パネルで、その事業の指標一覧と直近6期間の推移を確認します。

画面の見方

信号色

色意味とるべき行動
正常選択中の指標がすべて閾値内特になし
注視閾値に近づいている指標がある推移を確認しておく
要対応閾値を超えた指標がある詳細パネルで内容を確認し、必要なら計画点検へ

数値の脇にある区分

このアプリは根拠のない数値を作りません。数値の脇には必ず次のいずれかが付きます。

表示意味
実データ公開データから実際に取得できた値。出典も併記されます
取得待ち取得対象だが、まだ値が入っていない
未連携データがまだ接続されていない。数値は表示されません
「未連携」は不具合ではありません 売上・営業利益・人件費などの内部KPIや、訪日外客数・旅客輸送人員などは現在データが接続されていません。アプリは推測値で埋めず「未連携」と表示します。その指標では判断できないということ自体が判断材料です。

閾値を変える

信号色の基準は、事業ごとに変更できます。

  1. 事業カードの 監視設定 を押します（監視設定画面が開きます）。
  2. 左側の「指標カタログ」から監視したい指標にチェックを入れ、選択を確定 を押します。
  3. 右側で、指標ごとの閾値（例：日平均 35℃ 以上）と監視スパン（日次・週次・月次など）を設定します。
  4. 保存すると、その場で事業カードの信号色に反映されます。
監視設定は全利用者で共有されます 閾値や監視指標の変更は、あなたの画面だけでなく全員の画面に反映されます。誰が変更したかの記録は残りませんので、変更する際は関係者への共有をお願いします。

閾値の書き方

書き方意味
150.00円 超過水準が150円を超えたら発報
前週比 +15.0% 以上前週から15%以上上昇したら発報
前年比 −5.0% 以下前年から5%以上下落したら発報
前月比 ±10.0% 以上上下どちらでも10%以上動いたら発報

閾値の少し手前まで来ると注視、超えると要対応になります。

3計画点検

計画書を扱う画面です。画面上部で2つのモードを切り替えます。

AI経営ナビの計画資料の指定方法（共通ルール）
  • 戦略・計画の前提を洗い直す：data_internal/中期経営計画/ に置いた過去の確定版だけをリスト表示します。直近の計画書が一番上で初期選択されますが、利用者が別の期へ変更できます。
  • 戦略・計画を点検する：サンプルドラフトをリストから選ぶか、手元の計画・草案をアップロードします。複数ファイルにも対応し、アップロードした資料が優先されます。
  • グループ横断で計画を束ねる：上記と同じ資料選択レイアウトで、複数の事業計画をまとめて指定します。資料を横軸に束ね、前提・数値・資源配分・競合／相乗効果を比較します。
  • 計画と実態の乖離検証：登録済み確定版のリストから選ぶか、計画書をアップロードします。アップロードした計画がある場合はリスト選択より優先されます。
モード何をしてくれるか使う場面
計画定期診断 計画が置いている前提と最新の実勢を突き合わせ、乖離・リスク・確認事項を整理 計画策定直後、四半期レビュー前、取締役会への付議前
計画作成支援 草案の目的・読み手・論点を整理し、修正版と不足している根拠を提示（対話形式） 計画書・説明資料のドラフトをレビューしてほしいとき

計画定期診断の手順

画面上部のステップ表示が 1 計画書インポート → 2 対象を指定 → 3 自動照合 → 4 結果確認 と進みます。

  1. 左メニューの 計画点検 を開き、計画定期診断 になっていることを確認します。
  2. 計画書を読み込みます。方法は2つあります（下記）。
  3. 出力形式を選びます（単独事業／事業比較／HHHD全体）。会議での見方に合わせて選んでください。
  4. 対象事業を選びます。確認するデータは、対象事業と監視設定から自動で決まります。
  5. 診断項目を選びます。4つのうち必要なものだけで構いません。
  6. 診断を開始 を押します。
  7. ステップ表示が4段目まで進んだら完了です。結果が下に表示されます。

結果画面から条件を変えたいときは ← 診断条件に戻る を押します。

メニュー何をしてくれるか使う場面

回答を待っているあいだ

資料を読んで回答を組み立てるため、30秒前後かかります。そのあいだ、いま何をしているかが順に表示されます。止まっているわけではありません。

表示何をしているか

同じ表示が続くあいだは経過秒が加算されます（例：根拠を突き合わせて回答を作成しています 15秒）。

回答の見方

回答の下にある 根拠を見る を開くと、AIが参照した資料名・該当ページ・抜粋が一覧で出ます。社内資料の原本はこの画面から直接配信されません。重要な数値は、所管部署が管理する原本と出典元データで確認してください。

回答の下には 役に立った／改善が必要／回答をコピー が並びます。評価は 管理者機能 ＞ AI回答履歴 に記録され、改善の材料になります。

良い質問の書き方 「円安の影響は？」より「円安が旅行事業の収益に与える影響を、社内資料の根拠を挙げて整理してください」のように、対象事業とほしい形式を書くと精度が上がります。期間を絞りたい場合は「過去5年の」のように明示してください。

会話履歴について

左側に会話履歴が並び、クリックで切り替えられます。＋ 新しいチャット で新規に始められます。

会話履歴は保存されません ログアウト、ブラウザを閉じる、長時間放置のいずれかで削除されます。他の利用者から見えることはありませんが、翌日に続きを見ることもできません。残したい内容はコピーして手元に保存してください。

5総会QAアプリ

資料フォルダ 株主QAデータ/株主総会Q&A資料_<期>期/<コア>/…（例：株主QAデータ/株主総会Q&A資料_188期/都市交通/…）を正本として、コアを選ぶとAIが各部バラバラの形式のファイルから質問と回答を読み取り、共通フォーマットの台帳に整理します。以降は①質問作成 → ②回答作成 → ③点検・承認 → ④問答集の順に進め、承認済みの回答だけが問答集と当日検索に使われます。表示される機能はログインユーザーの役割で変わります。

資料フォルダの正式な命名は 株主QAデータ/株主総会Q&A資料_<期>期/<コア>/ です（例：株主QAデータ/株主総会Q&A資料_188期/都市交通/）。文字情報を持つPDFにも対応し、画像だけのPDFは取込対象外として通知します。

取込は見出し・番号・Q/A記号などの規則抽出を基本にし、規則で回答を確定できないファイルだけAIが補助します。フォルダ内の資料を無制限に横断して再構成する機能ではありません。

画面主な利用者目的
質問作成BU層質問一覧の確認、AIでQA自動分析（3分類＋追加質問のサジェスト）、削除予定の整理、手動追加
回答作成BU層回答・参考情報を人が入力（AI回答案は補助）。回答済みはまとめて点検リストへ統合
点検・承認BU層・事務局5つの点検の指摘（AI指摘・事務局指摘）に対応し、事務局が承認する
問答集BU層・事務局承認済みQ&Aの一覧・年度選択検索・Excel出力（非AI）
壁打ち経営層承認済みの回答をもとに、株主からの追及にどう答えるかをAIと練習する

0. コアの選択と資料の取込

  • 各画面の上部にある コアを選択 で対象コア（都市交通・不動産・エンタメ・情報・通信）を切り替えます。BU層（事業部担当・BUコア担当）は所属コア以外を開けません（🔒表示）。
  • 未取込のコアを選ぶと、AIがそのコアのフォルダ内ファイル（PDF・docx・doc・目次xlsx）を解析し、番号・分類・質問・回答・回答者を共通フォーマットで台帳へ登録します。PDFは文字情報を持つものが対象です。一度取り込んだコアは再取込されず、ファイルが変わったときだけ差分を取り直します。
  • 本文ファイル（回答つき）に加えて、目次・Q一覧にしか載っていない質問も「未回答」として登録します。本文ファイルと同じ質問（同じ部の資料番号が一致するもの、文言が実質同じもの）は登録しません。つまり一覧にはその期に想定している質問がすべて並び、回答ができているものと、これから作るものが状態で見分けられます。
  • 上部の ⤓ 資料を取り込む を押すと、その場で直近年度のフォルダを読み取り、台帳（DB）へ反映します。反映済みの状態で押すと差分だけを取り込み、フォルダに変更が無ければ 「取込済み（差分なし）」 と返します。
  • 過去の期（第187期など）は、株主QAデータ の下に 株主総会Q&A資料_187期 のような期フォルダを追加すると自動で認識され、問答集の期選択に現れます。PDFは文字情報を持つものが対象で、画像だけのPDFは取込対象外として通知されます。

過去の期は 株主総会Q&A資料_187期 のような期フォルダを追加すると、問答集の期選択に表示されます。

1. 質問作成

先頭の 質問一覧 タブが起点です。列は 番号｜想定質問｜事業部｜分類｜重要度｜年度点検｜状態 で、行を押すと質問・回答の全文、出典ファイル、更新履歴（誰がいつ何を保存したか）がポップアップで開きます。質問を検索 と 回答の状態 で絞り込めます。

AIでQA自動分析

  1. AIでQA自動分析 タブで AIで3分類する を押すと、過去の総会実績・資料内の変更記録・質問内容からAIが <1>変更なし／<2>微修正／<3>新設 に分類し、判定の根拠を添えます。
  2. <1>変更なしは今後も踏襲する定番質問です。分類にかかわらず、すべての質問は②回答作成で回答を確認してから ✓ 選択分を点検へ統合 で③の点検リストへ進めます（回答がある質問のみ）。
  3. <3>新設のうち期間限定イベント（例：2025大阪・関西万博）由来のものには削除候補が提示されます。削除予定に追加 を押してもすぐには削除されません。

削除予定一覧

  • 削除予定一覧 タブに削除予定の質問が理由つきで並びます。上司・事務局が確認し、削除を確定（事務局・管理者のみ）または 一覧に戻す を選びます。

AIでサジェストした追加質問

  1. 同じ AIでQA自動分析 タブの下段にあります。事業部名 を選び AIで追加質問を提案 を押すと、最大10件を提案します。
  2. 材料は3つだけです ── ①経営診断ホームの「今日のニュース」②SNSの注目テーマ（話題の増減・頻出語）③阪急阪神グループ公式サイトのニュースリリース。台帳にすでにある質問と似たものは出しません（材料が乏しければ提案数は10件未満になります）。
  3. 各候補には根拠（引用した見出しと日付、出どころのタグ：ニュース／SNS／ニュースリリース）が必ず付きます。確認のうえ 採用して一覧へ追加 または 除外する を押します。採用した質問はAI番号（A001形式）で一覧に入ります。
  4. 人が質問を足すときは 新規質問を追加 を押します。番号（Q連番）は自動採番されます。

2. 回答作成

回答は人がメンテナンスする前提です。一覧の各行の 回答を入力する でポップアップを開きます。

  1. 回答欄の右上の AIで回答案を作成 で下書きを挿入できます（編集して使う前提の補助機能です）。
  2. 回答の下の 参考情報 欄に、当日の補足に使う情報を人が追記します。
  3. 「2025年度」などの年度・時期の記載がある回答には 回答（参考情報）更新必須 のアラートが出ます。最新の内容へ更新してから 回答を保存 を押します。保存者・日時は更新履歴に記録されます。
  4. 回答済みの質問にチェックを入れ ✓ 選択分を点検へ統合 を押すと③へ進みます。未回答の質問は統合できません。更新必須アラートが残っている質問を統合しようとすると、プリチェックの確認が出ます。
  5. 統合を戻すときは 統合を取り消す を押します（承認済みは取り消せません）。

3. 点検・承認

②で統合された質問の一覧が基本です。列は 番号｜想定質問｜AI指摘｜事務局指摘｜指摘状態｜ステータス｜操作。指摘状態は「未対応指摘あり／指摘対応済み／指摘なし」、ステータスは「回答修正中／承認済み」の2区分です。

点検確認する内容
重複チェックコア内の事業部間・BU間で質問が重複していないか
網羅性チェックある部で回答済みの共通プロジェクト・事象が他部で未作成でないか
論理不整合チェック質問に対して論理性・一貫性のある回答か
整合性チェック類似質問の回答間で主張・数値が食い違っていないか
非開示情報チェック回答に非開示情報が入っていないか
  1. 全質問を点検する で機械＋AIの5点検を実行します。指摘はAI指摘列と指摘スレッドに入ります。
  2. 行を押すと指摘スレッドが開きます。事務局の コメントを追加 は事務局指摘として登録され、指摘状態が「未対応指摘あり」になります。BU層は回答を直し、指摘対応済みにする で事務局へ返します。
  3. 未対応の指摘がある間、承認する は押せません。事務局・管理者が承認すると「承認済み」になり、④問答集へ自動反映され、回答は編集ロックされます。修正が必要になったら 承認を解除 で「回答修正中」へ戻します（問答集からも外れます）。

4. 問答集

  • ③で承認済みになったQ&Aが、コア別（自分の所属コアが先頭）に並びます。年度 で期を選び、キーワード でAIを介さず検索できます。
  • Excel出力／Word出力 で、いまの承認済みQ&Aを1ファイルに出力します。

5. 壁打ち（経営層）

  • 総会前の準備で、想定される追及や言い回しをAIと練習します。承認済み問答を文脈に、発言を入力して 送信 すると、返答が届いた順に画面へ流れます。
  • 承認済みの回答をそのまま引きたいときは、④問答集の キーワード 検索（AIを使いません）を使います。

6. 管理（管理者機能）

  • 管理者機能 → 総会QAアプリ タブの「進捗・操作ログ」で、コアごとの進捗状況（取込済み・3分類完了・回答あり・点検リスト統合・承認済み）をマトリクスで確認できます。
  • 保存者の履歴（誰が・いつ・何を保存/承認したかの全操作ログ）もここで確認します。
  • 資料フォルダ（年度×コア）の取込状況と差分反映は、管理者機能 → 総会QAアプリ タブの「データ管理（総会QA資料）」で行います（最新データを反映）。コマンド python3 pipeline.py update --agm でも同じ処理が走り、どちらも更新ログに残ります。
