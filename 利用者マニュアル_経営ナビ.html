3センシングボード

6事業領域＋グループ開発室の外部環境と内部KPIを一画面で見て、今どの事業を優先して確認すべきかを判断する画面です。左メニューの センシングボード、またはホームの センシングボードへ → から開きます。

操作の手順

  1. 画面上部の帯で、公開データがいつ時点のものか、閾値超過が何件あるか（要対応・注視の事業名）を確認します。
  2. その下の「公開データ連携」の行で、取得の状態（正常／前回値／エラーの件数）を確認します。エラーがあっても、直近の成功値で表示は続きます。
  3. 事業のカード（島カード）の色点と矢印を見て、気になる事業のカードを押します。
  4. 右側の詳細パネルで、外部指標と内部KPIの現在値・5段階の変化方向・経営上の評価と、閾値超過の内容を確認します。
  5. 基準を変えたいときは ⚙ 監視設定 を押します（後述）。

画面の見方

島カードの色点（事業の状態）

表示意味とるべき行動
正常監視中の指標がすべて閾値内特になし
注視閾値に近づいている指標がある推移を確認しておく
要対応閾値を超えた指標がある詳細パネルで内容を確認し、必要なら計画の点検・乖離検証へ

色点は状態、矢印は変化の方向です。矢印は「大幅上昇／上昇／横ばい／下落／大幅下落」の5段階で、境目は指標ごとに違います（株価・為替は週次で±1%・±5%、金利は水準が小さいので±3%・±20%、など）。観測が2点未満の指標は判定なしになります。

数値の脇にある区分

このアプリは根拠のない数値を作りません。数値の脇には必ず次のいずれかが付きます。

表示意味
実データ公開データから実際に取得できた値。出典も併記されます
取得待ち取得対象だが、まだ値が入っていない
未連携データがまだ接続されていない。数値は表示されません
「未連携」は不具合ではありません 売上・営業利益・人件費などの内部KPIなど、接続されていない指標は推測値で埋めず「未連携」と表示します。その指標では判断できないということ自体が判断材料です。

詳細パネルの閾値超過の表示

  • 超過があると、影響度（★）、いつから続いているか（日数）、最新の値としきい値が出ます。センシングは知らせるだけで、計画への影響は第5・6章の点検で確認します。
  • データの取得が止まっている指標は「取得が止まっています」と出て、値が古いためアラームには数えません。
  • 超過が解消した指標は「解消」の印つきで3日間だけ残ります。

下位階層と権限

  • 事業カードの下には下位事業が並びます（都市交通は事業区分 → 運営単位の3階層、それ以外は2階層）。
  • 内部KPIは機密のため、閲覧権限のない事業は 🔒 権限が必要 のカードになり、数値は表示されません。権限は管理者が「ユーザー権限管理（経営診断）」の機能群で付与します（第8章）。
  • 表示デモで確認 を押すと、矢印の5段階表示と操作を試すためのデモ値に切り替わります（実データには影響しません）。もう一度押すと戻ります。

監視設定（閾値を変える）

島カードの ⚙ 監視設定 を押すと開きます。1段目で事業（6事業領域＋グループ開発室）、2段目でその下位の単位を選び、選んだ単位の監視指標と閾値を設定します。

  1. 左の「指標カタログ（共通プール）」で、外部指標・内部指標（標準3指標）から監視したい指標にチェックを入れ、選択を確定 を押します。
  2. 右の「この事業の監視指標」で、指標ごとの閾値（例：日平均 35℃ 以上）と監視スパン（日次・週次・月次など）を設定します。エリアを選ぶ指標は「表示エリア」でエリアを選びます。
  3. 閾値設定を保存 を押します。保存で確定し、島カードの色点に反映されます。
閾値の書き方意味
150.00円 超過水準が150円を超えたら発報
前週比 +15.0% 以上前週から15%以上上昇したら発報
前年比 −5.0% 以下前年から5%以上下落したら発報
前月比 ±10.0% 以上上下どちらでも10%以上動いたら発報
監視設定は全利用者で共有されます 閾値や監視指標の変更は全員の画面に反映されます。閾値超過はアプリ内のアラーム通知だけを行い、メール等の外部通知はしません。変更する際は関係者へ共有してください。

4AIとの壁打ち

社内資料・公開データ・センシング指標を根拠にAIへ相談する機能です。ホームの入力欄、または左メニューの AIとの壁打ち から開きます。

操作の手順

  1. 入力欄に相談したいことを書きます。何を頼めばよいか迷うときは ＋ プロンプト例を見る を押すと、5つの分類（資料を要約したい／文章を校正したい／業績の要因を分析したい／シナリオを比べたい／打ち手を考えたい）に例文が2件ずつ並びます。押すと入力欄に完成した依頼文が入るので、（記入）の部分を書き換えて送信します。
  2. 資料を読ませたい場合は、入力欄左下の ＋ から添付します（PDF・Word・PowerPoint・Excel・CSV・テキスト・Markdown、複数可）。添付は入力欄の上にチップで並び、×で外せます。添付した資料はその会話の中だけで使われます。
  3. ↑ を押すか Enter で送信します（Shift+Enter で改行）。
  4. 回答が長いときは、届いた分から順に画面へ流れます。途中で止めたいときは ■ を押します（届いている本文までが回答として残り、末尾に「停止しました」と付きます）。
相談の種類は自動で判定されます 入口は1つです。書かれた内容から「自由質問」「業績要因分析」「打ち手・シナリオ分析」のどれかを裏側で判定し、画面の見出しがその種類に変わります。業績要因分析のときは入力欄の上に「分析対象の業績データ」の行が出て、業績データを追加（実績・計画・比較期間が分かる資料）か テストデータを設定（サンプルCSV）を使えます。

回答を待っているあいだ

資料を読んで回答を組み立てるため、30秒前後かかります。そのあいだ、いま何をしているかが順に表示されます。止まっているわけではありません。

表示何をしているか
質問の意図を読み取っています質問を検索しやすい言葉に整理しています
社内資料・開示資料から根拠を検索しています該当しそうな資料を探しています
該当ページの前後を読み込んでいます見つかったページの前後も読み、文脈を補っています
根拠を突き合わせて回答を作成しています最後の工程です。ここが最も時間を要します

回答の見方

  • 回答は結論が先頭に来て、その下に根拠・反対材料・実行事項が続きます。
  • 回答の下の 根拠を見る（社内資料・出典リスト） を開くと、AIが参照した資料名・該当ページ・抜粋が一覧で出ます。社内資料の原本はこの画面から配信されません。重要な数値は所管部署の原本と出典元データで確認してください。
  • 各回答には 👍 役に立った／👎 改善が必要／⧉ 回答をコピー が付きます。評価は管理者の「AI入出力ログ」に記録され、改善の材料になります。
根拠に使われる資料の範囲 社内資料の検索は常に有効です。使われるのは、管理者が「ユーザー権限管理（経営診断）」であなたに付与したデータ群（data_internal のフォルダ）と、公開IR資料（有価証券報告書・公式IR資料・外部事例）です。権限台帳に登録のない利用者は公開IR資料だけが根拠になります。ウェブ検索は現在停止しており、インターネットへは出ません。
良い質問の書き方 「円安の影響は？」より「円安が旅行事業の収益に与える影響を、社内資料の根拠を挙げて整理してください」のように、対象事業とほしい形式を書くと精度が上がります。期間を絞りたい場合は「過去5年の」のように明示してください。

会話履歴について

左側に会話が並び、クリックで切り替えられます。＋ 新しいチャット で新規に始められ、会話のタイトルは後から変えられます。ホームの入力欄から送った相談は毎回「新しいチャット」として始まります。

会話履歴は保存されません ログアウト、ブラウザを閉じる、長時間（4時間）の放置のいずれかで削除されます。他の利用者から見えることはありませんが、翌日に続きを見ることもできません。残したい内容は ⧉ 回答をコピー で手元に保存してください。

5計画の策定・確認サポート

計画づくりと、できた計画の点検を支援する画面です。3つのカードから選ぶと、同じ画面の下にその機能が出ます（番号はありません。どれから始めても、必要な1つだけを使ってもかまいません）。

カード何をしてくれるか使う場面
戦略・計画の前提を洗い直す 前期計画の前提と最新データを比べ、新計画で考えるべき点と章立てを提示 新しい計画の策定に着手するとき
戦略・計画を点検する 計画・草案の論理、リスク、過去の指摘への対応をまとめて点検 計画書・草案を提出・付議する前
グループ横断で計画を束ねる 6事業の計画の前提のずれ、数字の二重計上、事業間の競合・相乗効果、資源配分を確認 各事業の計画をHHHD全体で束ねるとき

前提を洗い直す

  1. 「基準にする確定版計画書」で計画書を選びます。リストは data_internal/中期経営計画/ に置いた確定版で、最新が初期選択されています。
  2. 対象事業を選びます（複数可。HHHD全体 を選ぶと全社横断の観点で実行）。
  3. 前提洗い出しレポートを作成（3観点＋総括） を押します。外部指標・内部KPI・過去の経営会議論点と照合します。
  4. 結果は 総括／前提・情勢の変化／考慮すべきポイント／計画書の素案枠 のタブで読みます。
タブ内容
前提・情勢の変化前期計画の前提（為替・金利・需要・人流・単価・資材費など）を直近の実勢と1件ずつ突き合わせ、維持・要変更・新規追加を判定。指標にない外部情勢はAIの推論と明示
考慮すべきポイント外部環境の変化・内部KPI・過去の経営会議の論点の3系統から、重要度と反映先つきで列挙
計画書の素案枠新しい計画書の章立てを、章ごとの目的・書くべき内容・反映すべきデータつきで提案

計画を点検する

  1. 左の「点検する資料」に計画・草案をアップロードするか（複数可）、サンプルドラフト から選びます。未指定で実行すると、登録済みの最新確定版を点検します。
  2. 右の「突き合わせる議事録」に計画ミーティングの議事録をアップロードするか（pdf／docx／txt／xlsx、複数可）、サンプル議事録 から選びます。ここで指定した議事録の指摘・宿題が観点「過去の指摘」の判定基準になります。未指定なら取り込み済みの経営会議議事録から自動で拾います。
  3. 対象事業を選びます（単独・比較・HHHD全体は自動判定）。
  4. 点検レポートを作成（3観点＋総括） を押します。
  5. 結果は 総括／論理点検／リスク・論点／過去の指摘 のタブで読みます。総括には提出できるかの判断と、最優先で直す点が出ます。
観点確認する内容
論理点検結論・数値根拠・施策・KPIのつながりと、説明不足の箇所。必ず直す点・条件付きで許容できる点・問題なしの順
リスク・論点投資家や市場から出そうな批判・質問と、その影響の大きさ。起きる条件・先に動く指標・備え
過去の指摘過去の経営会議の論点・宿題に、今回の計画が答えているか

グループ横断で計画を束ねる

  1. 「横断比較する資料」に6事業の計画書とHHHD全体計画を複数アップロードするか、サンプル横断資料 から選びます。
  2. HHHD全体を点検 を押します。各事業の優劣は付けず、前提のずれ・数字の二重計上・事業間の競合／相乗効果・資源配分・セグメント別の構成比を点検します。

結果についてAIに聞く（共通）

各点検の結果の下から この結果についてAIに聞く の欄を開くと、その結果と直前の会話を文脈にして追加質問できます。根拠を詳しく／修正案／役員向け3点／判断条件 のボタンで定型の質問が入ります。この会話は点検結果専用で、AIとの壁打ちの履歴とは共有されません。

サンプル資料について サンプルから選ぶと assets/demo/ の資料が読み込まれます。デモ用に作成した架空の計画書・議事録で、実在の経営計画ではありません。前提条件を実勢とずらしてあるため、点検すると乖離の指摘が出ます。
数値は必ず原本で確認してください AIが読み取った数値には誤りが混じることがあります。会議資料や対外説明に使う数値は、必ず計画書の原本と出典元データで裏を取ってください。

6計画と実態の乖離検証

確定した計画を最新の実績データと比べ、ずれと対策を示す画面です。左メニューの 計画と実態の乖離検証、またはホームのカードから開きます。

  1. 「乖離検証する計画」で、登録済みの確定版から選ぶか、比較したい計画書をアップロードします（アップロードがある場合はそちらを優先）。
  2. 対象事業を1つ選びます（既定は HHHD全体）。
  3. 計画と実態の乖離を点検 を押します。実態はセンシングボードの外部指標と、取り込み済みの内部実績・レビュー資料から自動で拾います。
  4. 結果は、計画と実態のずれ → 放置した場合のリスク → 対策案の順に表示されます。第5章と同じく、結果についてAIに追加質問できます。

7フィードバックボード

左メニュー下部の フィードバック から開きます。改善提案や気づいた点を共有する掲示板で、全員が使えます。

  1. 上部の集計で、総件数と内訳（未着手・検討中・対応中・対応済）を確認します。
  2. 「新規投稿」で区分（UI/UX・データ・指標・診断ロジック・その他）を選び、投稿者名と内容を書いて 投稿する を押します。
  3. 一覧（投稿日・カテゴリ・内容・投稿者・状態・対応予定日）では、状態と対応予定日をその場で変更できます。

8管理者機能

左メニュー下部の 管理者機能 を開くと表示されます（システム管理者のみ）。経営診断 と 総会QAアプリ の2つのタブに運用機能がカードで並び、カードを押すと機能の画面へ移ります。画面上部のパンくずから戻れます。ここでは経営ナビ側と共通の機能を説明します（総会QA側は「マニュアル（総会QA）」）。

タブ機能できること
経営診断データ管理（内部資料） data_internal/ のフォルダ（IR公表資料・中期経営計画・株主総会議事録・経営会議議事録・社内資料など）ごとに資料数・索引済み数・最終更新・最終反映（日時／実行者）を確認し、最新データを反映 で差分を検索用DBへ入れる。資料一覧と更新ログも同じ画面。資料はフォルダへ直接置く（画面からの登録は行わない）。コマンド python3 pipeline.py update --internal でも同じ
経営診断ユーザー権限管理 ユーザーの追加・編集（ユーザー名・表示名・パスワード・有効／無効）、システム管理者の指定、データ群（data_internal のフォルダ。検索・AI相談・計画点検の根拠に使える範囲）と機能群（事業。センシングボードで内部KPIを見られる事業）の付与、無効化・削除、台帳のCSVダウンロード、権限の変更履歴。一括登録はコマンド manage_users.py import
共通AI入出力ログ AIとの壁打ち・計画点検・総会QAの質問と回答（伏字化して保存）、評価、機能別・利用者別の回数とToken。期間（30日など）・機能・利用者・評価・表示件数で絞り込み。「利用状況の詳細」で利用者別・利用者×機能の集計
共通エラー管理 期間（24時間／7日／30日／全期間、または開始日・終了日）を選び、エラーID・カテゴリで絞り込んで、発生箇所別・種類別・日別の件数と記録を見る。画面右下の通知に出るエラーIDで1行を特定できる
（センシングボードから）データ管理 →（公開データソース） センシングボードの「公開データ連携」の行から開く。12種類の公開データソースごとに推移と取得条件（取得月数・系列コードなど）を確認し、設定を保存／このデータソースを更新 を行う。運用担当向け
