1システム概要

阪急阪神グループの経営企画・IR業務を支援する社内Webアプリ。経営診断（AI相談・定期診断・計画点検・文案修正）と総会QAアプリ（質問予想から想定問答集作成までの6工程）の2つの業務モードを1つの画面系で提供する。回答は社内資料検索（RAG）の根拠つきで生成される。

項目内容
形態Gradio 6系の単一プロセスWebアプリ（Python）。全27ビューが1つの gr.Blocks に同居し、クライアントJSで表示切替（URLハッシュ同期）
認証Gradioの basic 認証（APP_CREDENTIALS）。アカウント単位のデータアクセス権限は権限台帳（後述 §6）で制御
AIOpenAI互換のチャットAPI（ai_client.py）。プロンプトは ai_prompts.py に集約し、モードごとに登録制
検索自前のハイブリッドRAG（SQLite FTS5 ＋ 日本語静的埋め込み1024次元）。索引 6,672断片。精度は正解付き168問で定量評価済み（別紙レポート）
規模app.py 約4,600行 / ui.py 約5,800行 / knowledge_rag.py 約3,200行 / agm/ledger.py 約2,100行 ほか。テスト約400件（pytest）

4検索（RAG）仕様の要点

  1. 候補絞り込み — FTS5（日本語n-gram）で最大600件。クエリが期を名指しした場合は、期メタデータの一致する断片を候補へ直接注入
  2. 採点 — 静的埋め込み（hotchpotch/static-embedding-japanese・1024次元）の意味0.9＋TF-IDF語彙0.1
  3. 期・名指しの構造照合 — 年月・◯年3月期・四半期・第N期・総会回次を索引メタデータと構造比較。資料名の名指し（「統合報告書2023」等）・系列名や話題の指し示し（「鉄道運輸成績」「ホテル×稼働率」等）も照合し、一致資料は上位帯へ
  4. シリーズ多様化 — 年月違いの同型資料は上位2件まで（名指しされた号は対象外）
  5. 足切りと表示 — 最良スコアの55%未満を除外。関連度は強・中・弱の3段、根拠が弱ければ「⚠ 強く関連する社内資料は見つかりませんでした」を明示
  6. 権限の強制 — 利用者の許可データ群を候補絞り込みのSQLで先に適用（順位付け前）
精度は python3 scripts/eval_search.py run（正解付き168問）で数分で再計測できる。検索パイプラインの変更時は前後で必ず実行する。

6アクセス制御の要点

  • ロール: contributor / bu_core / executive / secretariat / admin の5種 × 7部署。データは12の制限データ群＋公開IR（全員閲覧可）に区分
  • 未登録ユーザー: 閲覧専用（viewer）。公開IRのみ検索可、AGM工程の操作は全面不可（deny by default）
  • 強制ポイント: 検索SQL・AI相談・AGM工程権限・ライブラリ管理・回答履歴の5箇所で照合。UIの出し分けには依存しない
  • 設定手順: APP_ADMIN_USERS で初期管理者を指定 → 管理者設定「ユーザー・権限管理」で登録・付与（保存即反映・監査ログ記録）。詳細は開発者マニュアル §5.1
